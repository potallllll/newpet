# 11｜进入阶段 12 的验收准入清单

本表是[阶段 12 验收与冻结清单](12-v1-acceptance-and-freeze.md)的技术证据入口。配置及静态验证、数据库探针、真实环境联调分别留证。冻结后的可发布批次按实际证据及依赖逐项确认。

| ID | 范围 | 最少证据与通过条件 | 当前验证状态 |
|---|---|---|---|
| G12-01 | 源码与环境 | 单仓目录、实际分支、JDK／Spring Boot／MySQL／Redis／uni-app 精确版本、环境身份及版本锁由可重跑构建取证。部署目标和 CI 责任明确。 | 目录和版本线已设计，工程初始化待执行 |
| G12-02 | AppID 发布 | 引用 CI 受保护的批准名单，对双端真实发布产物和后端生效配置运行门禁。验证占位、试用、已知测试、受众互换、产物重打包均被阻止，实际上传使用已通过的摘要。 | 合成门禁已验证，双端实际构建和微信发布待执行 |
| G12-03 | V001 → V002 | 在两引擎跑空库和带存量升级；对目标托管 8.0 脱敏等量数据测 DDL 锁、存储、执行时长和 Flyway history。半成功场景可恢复。 | MySQL 8.0／8.4 本机 SQL 验证通过，服务环境待演练 |
| G12-04 | 端到端身份 | 微信两个有效测试 AppID。依真机受众、授权手机号、换号、同手机号换绑、旧双端失效、冲突不合并、同 OpenID 跨 AppID 不当作同一人及无 UnionID 情况取证。 | 数据库探针已验证，应用和真机待执行 |
| G12-05 | 权限、撤销与停用 | 本店老板、员工、顾客、跨店顾客；任职停用／恢复／返聘、门店停用／恢复、新旧 Redis 会话、改绑与写操作并发。原状态、经办及身份隔离可追溯。 | 当前 SQL 规则探针已验证，控制器和 Redis 故障待执行 |
| G12-06 | 媒体和密封 | 私有对象真实校验、不可变版本、越店引用及替换旧链接拒读；实测接宠健康照片直接关联原入住，以及照护照片只关联照护事件。模拟 KMS 不可用、密钥轮换、历史发码无密文、同键响应丢失及期限到点。验证原码和原截止一致、过期保留回执。 | 数据归属及窗口约束已验证，KMS、对象网关和真实上传待执行 |
| G12-07 | 主链与金额 | 双端完成预约→门店确认→洗美开工→完成→收款→顾客回看；另跑两宠寄养分批挂单／收款、商品预占、余额、赠券充值及两种充值退款模式。实收与退款原单可对账。 | 对接阶段 08 的 59 条验收用例，真实联测待执行 |
| G12-08 | Outbox 与租约 | 双 worker 领取、崩溃重启、旧令牌回写拒绝、站内唯一；微信明确失败可重试、结果未知保留人工核对。Redis 清空后 DB 持续扫描。 | SQL 竞态已验证，应用与真实渠道待执行 |
| G12-09 | 库存与幂等 | 预占到点、成交／超时竞争、关闭自动取消、真线下成交补记及两次支付重放。校验总库存、预占和流水。清理后用旧键／旧版本重放，须能证明无重复副作用。 | SQL 竞态及部分清理守卫已验证，API 与跨域事务待执行 |
| G12-10 | 限频和日志 | 在两个 API 实例验证限频击穿、可信 IP、重试提示和 Redis 故障降级。用合成凭证和标记字段检查日志、网关、APM、DLQ 和异常采样无敏感原值。 | 设计待应用联测和容量校准 |
| G12-11 | 备份与恢复 | 算出 MySQL 恢复点差及恢复耗时，验证跨段 binlog 连续回放、对象版本、密钥、恢复纪元和账本对账。至少一次包含恢复点后发生换绑／停用的样本。 | 本机逻辑恢复和定点重放通过，生产 RPO/RTO 待演练 |
| G12-12 | 部署与发布顺序 | 关闭完整平台 Web 验双端高频流程；关停 AI、媒体或微信订阅时核心可继续。分阶段启用受条件能力，平台账号／代办按阶段 05 后置。 | 门禁矩阵及降级路径已设计，双端部署待执行 |

证据按环境、构建 SHA、数据库迁移版本、执行时间、用例 ID、请求 ID、必要的当前角色及对象事实保存。允许用合成数据签收数据库证据，微信能力和真实基础设施由实测取证。未跑项留 `not_run`，环境阻塞项留 `blocked` 并列依赖。先验收核心路径，再启用受条件能力。DEC-EXEC-01／02 尚需登记实际开发分支、部署目标、AppID／环境、联调责任及正式开发授权。
