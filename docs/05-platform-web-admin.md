## 1. 使用者与批次

平台人员在网页端处理需要跨店权限、正式审核或异常核实的事项。老板和店员在小程序内接预约、开单、服务、收款、入库和管理本店。完整平台后台后置。小程序功能开放前，应能找到负责处理的有权平台人员、实际可用的入口和结果回写；缺其一时，对应功能延后开放。

## 2. 首批需求

| 模块 | 平台入口与处理内容 | 双端结果与来源 |
|---|---|---|
| 门店资料审核 | 待审核列表、原有效资料与申请内容对比、通过或退回、历史。营业执照只向有权角色显示。 | 审核通过后发布有效版本；同店一份待审、撤回与批准并发、通过后168小时限制按[04 §3.0.6](04-staff-miniapp.md)。 |
| 门店与身份异常 | 查询门店和账号、核对原任职和绑定证据、查看待收尾业务。处理两个既有账号冲突、唯一老板号码异常等个案。 | 安全核验前保持冲突阻断，按[03g](03g-customer-identity-security.md)保留原身份和历史。账号恢复的证据与操作资格须另行确认。 |
| 门店停用影响核对 | 停用前查看在住、未结算、预占、争议、上门喂养和待领实物。停用后按原记录追踪去向与处理结果。 | 上门喂养按[03j](03j-customer-home-feeding-marketplace.md)接续；领取门店停用按[03k](03k-customer-loyalty-points.md)处理。其他业务由平台沿原记录核实承接，受限收尾的角色、动作和准入另行确认。 |
| 消费争议与证据 | 待审核、原投诉/回应/补证、证据审核、脱敏预览、裁决及确认已解决。客服按原案处理异议。 | 7天回应、3天补证及平台裁决按[03h](03h-customer-risk-feedback.md)。门店看其有权内容，顾客只读可见内容与对应结果。 |
| 食品风险与厂家回应 | 按原案和批次查询，联系厂家、录入回应、审核发布；查询该店知悉状态。 | 平台联系厂家，门店仅知悉。热度、集中反馈有效期和工单归属按[03h](03h-customer-risk-feedback.md)、[03f](03f-customer-messages.md)。 |
| 顾客风险与授权 | 审核门店提交的顾客风险；根据认证手机号冲突或授权变更申请核实。 | 原有分项同意、限频和展示期不变。顾客端不展示风险记录，权限以[03h](03h-customer-risk-feedback.md)为准。 |
| 原单异常与账本核实 | 用单号定位原消费单、商品需求、充值记录或兑换单，留处理依据。纯线下收款错录按03d追加核实后的纠错；商品补记遇库存或证据冲突，保留事实等待人工结果。 | 仅有权人员执行已获准的动作。原始收退款、消费及库存历史保留；不追加虚构资金流。顾客和门店各读有权结果。见[03d §11.3](03d-customer-orders.md)、[03e §13.1](03e-customer-products.md)、[03c §4.3](03c-customer-wallet.md)。 |

## 3. 页面共用要求

- 支持按原单号或原案号直达详情；详情保留来源门店、当前状态、历史时间线及有权动作。列表、详情、下载与附件访问均按角色和业务范围校验。
- 审核或异常处理记录实际操作人、服务端时间、对象及前后结果。请求重试不重复作出裁决、追加纠错、扣库存或发通知。已批准记录不得被旧撤回请求覆盖。
- 客服登记、审核裁决和账本纠错分别校验权限。复用现有 evidence.review、complaint_review.decide、complaint_review.resolve、customer_risk.review 和 reward_fulfillment.manage 的原适用范围。新增角色或权限标识先在阶段08确认。
- 页面搜索、待处理队列筛选、平台登录与凭证核验、纠错字段、审计读取及通知回写在正式接口与权限设计时登记。一线店员可用原单号联系客服，结果去原业务详情查询。

## 4. 随对应功能开放

总仓发货、积分实物错发或未收到、广告素材和启停、顾问门店权益在相应模块启用时提供平台入口。其中积分异常沿原兑换单核实，保留门店停用自动退积分和720小时系统默认领取的区别，核实后的补发或积分处置权限待该模块确认。报表、批量运营与外部旧系统导入按后续阶段规划。

## 5. 第一轮评审场景

1. 门店撤回修改申请与平台批准并发，只有先成功的动作生效。
2. 老板失去原号码，已有在住寄养；平台核验过程可追溯，历史与资金不迁移。
3. 门店停用时存在在住、欠款、未发奖励及已接单上门喂养，各原单遵循其所属业务规则。
4. 平台处理消费争议裁决、食品厂家回信、风险撤权，客户端和店员端可见范围正确。
5. 实收100元误录80元，核实后原录入仍可追溯，统计按真实100元显示，资金渠道没有产生第二次收款。无证据、越权或涉及已发生退款／钱包的尝试不写账。
6. 商品原需求已超时且已真实交货，原单不恢复；可核实且库存满足时只补记一笔。库存冲突时保持原流水，交平台核实。
