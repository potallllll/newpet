## 通用布局

- 配色、字体和字号角色沿用[顾客端设计系统](10a-customer-ui-design-system.md) §2.3～2.5。实际触控热区至少 **44×44 逻辑 px**，相邻热区互不重叠。
- 列表和表单用单列纵向布局。搜索和筛选在列表上方，常用入口整行可点，状态用文字标明。服务选择与商品选购提供常用置顶区；预约管理顶部提供“列表／今日时段”。开单、预约确认、服务推进、结算等页面的当前主操作放在底部安全区上方，随页面状态显示，键盘展开时保持可达。次要动作放在详情内，避免与主按钮并排挤压。
- 底栏用于一级页面。进入表单或详情后可返回原列表，保留查询条件和滚动位置。服务端确认成功后再显示成功结果。原开单／入住／结算仅在小程序本地临时恢复输入，提交前查原单或请求，提交成功或退出即清空；消费争议回应与补证仍直接提交。原结算同屏呈现应收、已记实收、退款、本次金额与记账时间。顾客线下合并转账后，各独立原单只登记自己的实收份额。

## 五项底栏与页面顺序

底栏从左到右固定为 **工作台 → 业务 → 快捷入口 → 客户 → 我的**。业务动作与权限见[店员端需求](04-staff-miniapp.md) §3.0、§3.2。

| 页面 | 从上到下 |
|---|---|
| 工作台 | 待处理（预约确认 → 商品处理 → 上门喂养 → 其他）、服务中（今日洗美 → 在住寄养 → 其他服务）、异常与临期（投诉回应 → 寄养异常 → 洗护异常 → 其他异常）。跨天仍需办理的事项按业务规则保留，消费争议卡突出 **7 天回应**及真实截止信息。 |
| 业务 | 预约管理 → 商品处理 → 寄养 → 上门喂养 → 消费争议 → 订单与收银 → 洗美。洗美内查看待接宠、服务中、待结算和历史记录。 |
| 快捷入口 | 临时开单 → 会员开单 → 客户查询 → 寄养入住。客户查询和寄养入住进入原业务页面。 |
| 客户 | 统一搜索 → 按顾客／按宠物切换 → 列表；新增顾客保留独立入口。进入当前顾客后可带入会员开单或寄养入住。 |
| 我的 | 员工与门店信息 → 我的工作记录 → 我的业绩 → 通知设置 → 账号与安全 → 帮助与反馈 → 老板管理（仅本店有效老板）→ 退出登录。 |

## 老板管理菜单

1. 门店资料
2. 营业与预约设置
3. 服务项目管理
4. 员工管理
5. 经营统计
6. 优惠券管理
7. 创建邀请码
8. 操作日志

员工管理内固定 **员工列表 → 邀请员工**。老板管理的页面与接口均校验本店有效老板身份。
